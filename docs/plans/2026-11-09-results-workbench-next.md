# 成果工作台：复用、双桌面与工作回顾设计

日期：2026-11-09。状态：三阶段已在 0.3.0 实现；实测范围与边界见 `../verification/2026-11-09-v03.md`。下文保留设计依据，实际首版按月回顾，未加入任意周范围或通用多窗口系统。

## 1. 目标与产品取舍

让使用者在持续对话后，逐渐拥有一批找得到、看得见、用得上的个人成果。回来时能回答：我做过什么？什么值得留下？这次可以从哪件旧成果继续？

命名采用用户确定的“成果工作台”。保留 @local/desk-workbench、desk 投影和面板 ID，不因显示名称更改破坏安装与历史数据。

比较三个侧重点：

| 方向 | 好处 | 局限 | 取舍 |
|---|---|---|---|
| 对话计数、勋章和连续打卡 | 容易制造短期反馈 | 聊天多不代表做得好，重复修改也会刷计数 | 不作为核心机制 |
| 作品收藏与复用 | 下次工作能直接受益，价值可验证 | 需要稳定作品身份和持久元数据 | 优先建设 |
| macOS 风格和回顾动画 | 更熟悉、更有探索和回看意愿 | 单独做容易成为装饰，不能弥补数据不可靠 | 建在同一成果与版本体系上 |

推荐主线：自动收集 → 看过作品 → 标记重要 → 从旧成果开始新工作 → 看见成果之间的积累。用户不用每轮填写归档表。

## 2. 同一份成果，两种桌面

顶部提供“物件桌面 / macOS 风格桌面”切换，记住当前使用者的选择。切换只改变呈现方式，不复制成果、不清空筛选、不丢失正在看的作品。

### 物件桌面

沿用投影幕、电脑、相册、书架等物件，适合轻松浏览和回来收看成果。重要作品可以作为桌面上的置顶展示；点击仍进入共用的成果浏览器。

### macOS 风格桌面

在 Harness 面板内呈现熟悉的桌面感觉：顶部菜单栏、壁纸、文件图标、Dock、Finder 风格浏览窗口、窗口阴影和有限的半透明材质。

- 桌面主要放重要成果与最近工作，其他成果从 Dock 的分类入口或成果浏览器进入，避免几百个文件铺满桌面。
- 文件以真实封面/缩略图、名称、类型呈现。文件夹对应项目、成果分类或重要成果集合，都是索引视图，不擅自移动磁盘文件。
- 桌面图标支持双击打开；触屏保留单击按钮与明确的打开入口。Enter 打开、Escape 关闭，窗口按钮有可访问名称。
- 普通浏览窗口支持移动、聚焦和最大化；小屏退化为单窗口。第一阶段不做任意多窗口、复杂吸附或模拟整套系统设置。
- 这是成果工作台内的桌面，不接管用户的真实 macOS 桌面，也不把打开成果的动作变成未经明确触发的系统操作。

共用：搜索、主题/状态筛选、作品详情、预览、重要标记、复用、回原会话、版本与回顾。两种桌面不维护两套业务逻辑。

验收：同一成果在两种桌面中看到相同内容和标记；切换后可继续看同一件作品；390px 宽度不横向溢出；键盘可完成打开和关闭。

## 3. 重要成果：先让用户决定什么值得留下

成果卡片和详情页提供星标，名称为“标记重要”；再次点击取消。标记只影响个人整理，不发消息、不调用模型、不删除文件。重要列表在两种桌面中都能直接打开。

详情允许写一句“为什么重要 / 下次怎么用”，为空也可标记。后续可以支持集合，如“演讲材料”“常用模板”，不要求用户一开始建立目录体系。

明确区分：
- 标记重要：保存这件成果的个人标记。
- 保存此版本：保存可回看的实际文件内容。

如果原文件位于临时目录、已不可读，或只有压缩后的保存预览，界面显示真实情况。星标本身不宣称原文件已安全备份，也不把预览冒充原始 PPT/图片。

验收：重启、历史重放及切换桌面不会丢失星标；同名不同文件不错误合并；来源会话被移除后，已保存版本和个人备注仍能独立解释来源状态。

## 4. 复用：从旧成果开始，而不只是重新打开

三个常用动作：

1. **继续修改**：回到原会话，保留作品身份与来源。
2. **以此为基础**：选择一个或多个旧成果，带到新任务，填写这次想改变的部分。
3. **按这个做一个**：复用成功作品的结构和做法，替换这次的内容与约束。

具体例子：用户打开去年的发布会演示稿，点击“以此为基础”，填“保留结构，替换为今年数据”；准备页列出旧稿、相关修改意见和这次要求，用户确认后开始新任务。新任务产出的演示稿链接到原稿，原稿本身不被覆盖。

准备页必须展示实际带入的内容：文件/已保存版本、选中的讨论摘要、用户备注、新任务要求。默认只带与这件作品有关的内容，不整段复制整个历史会话。点击“开始任务”才发送请求，不因浏览、星标或切换桌面自动调用模型。

版本选择与路径处理：
- 有已保存版本：可明确选择“保存时版本”或“当前文件”。
- 只有当前路径：先验证可读取；标注这次读取的是当前内容。
- 文件已丢失：给出保存预览、其他版本或回原会话的入口，不制造一个不存在的文件附件。
- 插件不覆盖原路径，提交提示要求使用新文件名；Agent 后续写入由 Harness 权限及用户指令约束，插件不承诺拦截所有工具写入。
- 原稿与新稿记录 derivedFrom 关系，可回看“这次工作从哪里开始”。

实现已核实 Harness 通用文件上传、receipt、工作区会话创建与 requestId 去重契约；全部来源通过通用文件通道携带完整字节，图片也保留原始文件。真实 Host 隔离测试覆盖 HTML 演示稿、PNG、Markdown 文档。未逐一验证所有 Office 格式的模型理解效果。

“按这个做一个”先生成用户可编辑的任务草稿：沿用哪些结构、替换哪些材料、保留哪些审阅要求。不自动把一次成功归纳成成熟 Skill；只有真正再次使用并验证后，才考虑沉淀为模板/方法。

验收：准备页列出的来源与实际提交内容一致；发送失败可重试，不重复创建任务；新旧成果关系保留；计数只在复用任务确实创建后增加。

## 5. 成就感：让积累可见，避免只奖励聊天数量

桌面优先呈现可验证的积累：
- 你标记的重要成果，形成自己的代表作品区。
- 最近新增的作品，连续修改同一文件聚合展示，不每次调用都算一件新作品。
- 从旧成果继续做出的新成果，展示实际复用关系。
- 同一项工作从想法、草稿到可用版本的变化；没有版本数据时只展示有证据的事件。

月度回顾可以表达：“这个月新增 5 件作品，标记了 2 件重要成果，3 次工作从已有成果开始。”数据需标注时间范围和计数规则；计数来自真实作品/标记/复用记录，不从模型估计，不把“本轮完成”当作“用户认可”。

讨论仍有价值：没有文件的会话可以由用户标记为重要结论，收藏自己认同的片段，而不是把每一段较长回复自动算作代表成果。

回顾中的一个具体变化应当可以点击核实。例如点击“3 次复用”能看到对应的旧稿、新任务和新成果；没有足够数据时显示普通最近工作，不生成空洞的成就文案。

初期不需要积分、排行榜、连续签到或催促用户多聊。更有价值的反馈是：“你上次留下的东西，这次帮上忙了。”

## 6. 工作回顾：同一时间数据，两种回看方式

### 时间回顾（Time Machine 风格）

从桌面的“回顾”入口进入，按周/月浏览。成果卡片沿时间轴排列，当前日期在前，滚动或按方向键后退到过去。每个时间段展示代表作品、重要标记和新旧成果关系。点击进入作品或版本详情，退出回到原桌面位置。

首版只动画化卡片层叠、深浅和位移，不同时挂载几十个 iframe、视频或完整文档；资源只在打开时读取。默认手动浏览，不自动播放声音。

### 工作手册（翻书风格）

同一批数据按月形成章节：封面、这一月的作品、重要成果、一次复用或修改过程。翻页可以采用纸张转动的视觉效果，内容仍是可选择文本和可点击作品，不把所有页面截图化。更适合慢慢回顾和展示自己的积累。

建议顺序：先做好时间回顾，再添加翻书呈现。两种方式共用回顾数据，不各自生成不同事实。

### 历史真实性

当前投影只保留当前文件引用、有限摘要和记录次数；它不是版本归档。对于过去的会话：
- 可以根据事件时间展示“当时发生了哪些工作”。
- 点开未归档的文件，明确显示“读取当前文件”；不能称为“恢复到当日版本”。
- 不能从记录次数、工具调用次数或截断的 body 自动重建历史原稿。

从新版本启用后，用户可以“保存此版本”，将内容复制到插件管理的持久目录并记录 hash、格式、时间、来源。只读原文件，不修改源文件。保存前说明本地副本及大小；写入失败不显示为已保存。相同内容按 hash 去重，动画只加载封面。

回顾仅浏览，不等于系统恢复。若未来提供恢复/替换原文件，它是单独操作，展示目标和差异后取得明确确认。

验收：时间顺序正确；缺少快照时明确标注；已保存版本可在原文件删除后打开；动画可跳过，遵守 prefers-reduced-motion；读屏、键盘和普通列表均可使用。

## 7. 数据基础与模块边界

现有只读事件折叠继续负责发现工作，不负责存放用户星标。需引入以下独立数据：

| 记录 | 最少字段 | 用途 |
|---|---|---|
| Artifact（稳定成果身份） | artifactId、来源会话/事件、路径/附件别名、类型 | 文件改名、分类变化后仍指向同一成果 |
| Personal metadata | artifactId、重要标记、个人备注、更新时间/revision | 保存用户判断，不被会话重放覆盖 |
| Saved version | versionId、artifactId、内容 hash、持久引用、时间、格式、封面 | 真实版本回看与复用 |
| Reuse relation | 来源 artifact/version、目标任务、派生成果、创建时间 | 解释积累，支持复用回顾 |
| View preference | 桌面模式、必要的窗口位置 | 保持熟悉的桌面，独立于作品数据 |

已存在的 file:path / attachment:id 不能直接当永久用户标记主键。先为现有成果分配稳定 ID 与别名映射，按确证的来源关联迁移，禁止单凭相同文件名合并。

Host 负责持久元数据与保存版本，提供经过 Harness 认证/授权的读写接口；Client 共用一个数据层，只提供两种桌面渲染器和两个回顾渲染器。metadata 更新使用 revision 防止两个窗口互相覆盖。用户在重新折叠 projection 后，星标、备注、版本和复用关系必须保持。

文件内容复制与元数据更新需具备失败恢复：先写临时副本、校验成功再发布版本记录；中断不留下“已保存”假状态。取消标记不删除文件或快照；清理副本另设可审查的操作，不能误删源文件。

## 8. 开发顺序与交付物

### 第一阶段：重要成果与复用（优先）

1. 核实 Host 持久存储、认证 RPC、新任务创建和文件携带契约。
2. 完成稳定成果 ID、别名映射、星标/备注存储及迁移验证。
3. 两个入口：重要成果、以此为基础；先使用当前物件桌面验证实际价值。
4. 实现可预览的复用准备页、明确提交和来源关系。
5. 用真实演示稿、图片、文档分别完成“旧成果 → 新任务 → 新成果”验证。

交付：重启不丢的重要成果；至少三种成果类型的真实复用链路。不能只通过模拟接口证明通用文件已加入任务。

### 第二阶段：双桌面

1. 把现有桌面与成果浏览器拆为共用数据层、呈现层。
2. 增加模式切换和偏好保存。
3. 完成 macOS 风格菜单栏、Dock、图标和 Finder 风格窗口。
4. 对同一真实成果在两种桌面下复测打开、星标、复用、搜索与窄屏。

交付：切换前后作品身份、用户标记、浏览进度一致。

### 第三阶段：版本与时间回顾

1. 完成显式保存版本、内容去重、来源信息和失败恢复。
2. 根据可验证事件与快照构建按周/月的回顾数据。
3. 实现 Time Machine 风格时间回顾，支持普通列表与减少动画。
4. 验证删除原文件后已保存版本仍可查看；存量无快照数据不伪装成历史版本。
5. 再增加工作手册/翻书渲染器，复用同一回顾数据。

交付：能看见自己的积累，也能准确区分“当时的版本”和“现在的文件”。

## 9. 建议的第一轮真实验收

选择用户已有的一份演示稿、一张图和一篇文章：
1. 标记重要，分别写一句下次用途。
2. 重启，检查标记仍在。
3. 从演示稿发起下一次工作，确认原稿未被覆盖、新稿有关联。
4. 切换两种桌面，同一成果和浏览状态不变。
5. 保存新稿版本后修改/移动原文件，回顾仍打开保存时内容。
6. 打开某月回顾，数字与实际作品、重要标记、复用事件逐项对应。

核心成效用实际复用、找回成果所需步骤、重复解释是否减少来判断；“聊得越多”应表现为个人资料与作品逐渐丰富，而不是单纯数字上涨。

## 10. 生态定位补充（用户提供的 Harness 生态说明）

用户补充：Harness 希望成为 Agent 时代的操作系统，提供稳定基础能力与多数人需要的通用功能；内置功能同样可被第三方插件替换，鼓励社区形成用户日常选择。

据此，成果工作台定位为可替换、可个性化的个人成果应用。会话创建、文件接收、模型执行、权限与连接认证继续依赖 Harness。插件拥有个人标记、版本副本、复用来源关系与呈现偏好，不自行重建 Agent 调度器或通用文件系统。macOS 风格仅是这个应用的一种桌面呈现。

差异化集中在“用户怎样留下判断、再次使用旧成果、看见作品的演变”，而不依赖官方永远不提供成果列表。使用公开可验证的接口，保持数据身份与展现分离，后续能把官方新增基础能力接进来。
